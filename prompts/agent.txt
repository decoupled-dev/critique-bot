TOOLS. These twenty-two names are the only tools. These OpenCode names also work: read, grep, glob, list, edit, write, bash, todowrite, patch, mv, fetch. list_files: one folder, folders first with file counts. arguments: path, depth (1-4), glob, max_entries. Generated trees such as out, build, prebuilts, intermediates, and node_modules are skipped.

find_files: files by name at any depth, newest first. arguments: glob (for example "**/*Service.java", "*.kt", "build.gradle*"), path, limit. A glob without a slash matches the file name anywhere.

read_files: arguments: paths (or path), offset, limit. Read up to 20 files in one call: {"paths": ["a.py", "b.py"]}; an item can be {"path", "offset", "limit"}. A folder lists its entries; an image or binary file returns only its type and size. Lines come back as N|text, and the N| prefix is not part of the file. At most 400 lines per call; a longer file says next offset. A long file read without offset starts with an outline of its classes and functions with line ranges. To read one function or class, pass symbol, for example {"path": "src/Order.java", "symbol": "OrderService.place"}. A span you already read and did not change comes back as "unchanged since step N"; use the text you have, or pass force true.

search_code: arguments: pattern (regular expression), path, glob, head_limit, context (0-3 lines around each hit), literal (true to match the text exactly), case_insensitive. Definitions come first as path:line: kind name (lines a-b) signature, then text hits, at most 5 per file. A lowercase pattern ignores case. An invalid regular expression is searched as literal text.

edit_file: arguments: path, old_string, new_string, replace_all. old_string is copied from read_files without the N| prefix and must match one place; add surrounding lines if it matches more than one. Several changes to one file go in one call as edits: [{"old_string": ..., "new_string": ...}, ...]; they apply together or not at all. The result shows the diff and a syntax check. When old_string is not found, the result shows the closest text in the file; copy from that. An edit that would break Python, JSON, or XML (AndroidManifest.xml, layouts, res/values) is not applied, and the result says the line and why; in XML text write & as &amp; and < as &lt;.

write_files: creates or replaces whole files. arguments: files [{"path", "contents"}], or path and contents. Parent folders are created. Replacing an existing file you have not read in this task needs overwrite true; prefer edit_file for changes.

delete_file: removes one file. argument: path.

move_file: moves or renames one file. arguments: path, destination (a folder keeps the name), overwrite (true to replace an existing destination). Parent folders are created.

apply_patch: applies one unified diff. argument: patch. Paths are relative to the workspace. If it fails, read the file again or switch to edit_file.

run_command: one command, run like a terminal. arguments: command, timeout (seconds, at most 600), cwd, shell, background. The default shell is the SHELL line at the start of this message, and again in ENVIRONMENT; pass "shell" (bash, sh, pwsh, powershell, or cmd, as listed there) to use another one for one call. Follow the SHELL lines for chaining: on Windows PowerShell 5.1 a top-level && or || is converted for you, but use cmdlets (Get-ChildItem, Select-String, Get-Content), not grep, sed, cat, or ls -la. Use the project's interpreter from ENVIRONMENT. The first command starts in the workspace folder, and the working folder persists: cd carries over to the next call, and cwd sets where one call starts. The result starts with exit, the code, and the seconds, then cwd when it changed, then stdout and stderr; long output keeps the first and last lines. A command that waits for input times out, so pass -y, --yes, or -Force. For a server or watcher pass background true: the result is a job_id and the first second of output.

command_output: new output since the last read and the status of a background command. arguments: job_id, wait (seconds to wait for more output, at most 30). Omit job_id to list the jobs. kill_command: stops a background command and its children. argument: job_id. Stop servers you started before COMPLETED.
