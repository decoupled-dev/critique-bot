# Decisions

Dated record of choices that change the plan. Newest first.

| Date | Decision | Why | Stage |
|---|---|---|---|
| 2026-11-27 | The verified flow is on by default in crit's sessions (`flow: auto`: bug fixes get the whole flow, features and refactors test + review, questions and ops plain); a bare `run_agent_loop` stays plain; an unclear task runs plain unless the one-question classifier (model API backends only) decides | M2's "on by default for bug fixes"; the engine's own scripted tests and helper code keep their behavior; a web chat has no side session for the classifier question | 7 |
| 2026-11-27 | The engine reads the review JSON (`risk`, `comments[].severity`) itself (`flows/verified.parse_review`), the same contract as the review mode | `review_comments` is an app module the engine may not import; the contract, not the parser, is what is shared | 7 |
| 2026-11-27 | The TEST before-run swaps the task's pre-task copies (the undo checkpoint) in for the run and puts the task's versions back, instead of a git stash or a worktree | Works without git and on any tree size; the copies already exist; nothing touches the user's stash. Cached `.pyc` of the swapped files are dropped, since a same-size edit in the same second would be served stale | 7 |
| 2026-11-27 | A rejected attempt does not revert the files: the next attempt is told to undo what did not work, with the rejected diff | Reverting the user's tree on a heuristic is not safe; the diff and the reason are what ChatRepair's memory needs | 7 |
| 2026-11-27 | The no-progress counter starts at the first failing-test count seen; before that the state's token budget is the stop. Budgets are estimated tokens (characters / 4) | A model that runs no tests would otherwise be stopped after 12 turns of normal editing; server usage is per process, not per state | 7 |
| 2026-11-27 | A plan trigger in auto mode enters plan mode and approves the plan itself; other modes ask (a `request` event on API sessions; unattended runs answer no) | "In auto mode, enter it": an auto run has no one to approve a plan, and a plan without approval would end the task unchanged | 7 |
| 2026-11-27 | `crit run --json` ends with `{"type": "final", "code", "changed", "evidence"}` after `session_closed` | The plan's "final object"; every earlier line stays an event | 7 |
| 2026-11-27 | Keep building crit on its own codebase; do not fork Qwen Code, OpenCode, OpenHands or Hermes. Continue the plan as written | Considered after comparing with Qwen Code and the harness survey arXiv 2609.00006 (11 systems): crit already covers all seven harness subsystems, is ahead on OS sandboxing (only Codex and Gemini CLI have one) and on AOSP depth (none of the 11 address it); a fork would mean porting those into another codebase. An MCP server exposing crit's AOSP tools to other agents stays an option for later | all |
| 2026-11-27 | Domain packs are built-in content under `critique_bot/packs/<name>/`, off until `"packs"` names them; loaded by the Stage 6 extension loader as trusted (no `crit trust`); `packs` is a security key | One loader and one registry for every extra tool; a cloned repo must not switch on a tool that reaches a device or a looser sandbox preset | 9 |
| 2026-11-27 | Manifest tools take `actions` (per-action argv, required args, value patterns, read_only, risk, `device`); only crit's own packs may name a Python `handler` | "One tool per area with an action" keeps the tool count low for small models; a pack needs Python behind some actions (triage, test selection), user manifests must stay argv-only | 6, 9 |
| 2026-11-27 | A device-changing call asks in every mode, even with `confirm_risky: false` (permission key prefix `device:`; one line in the engine) | Plan risk: flashing or wiping a device needs explicit confirmation even in auto mode; evals set `confirm_risky: false` | 9 |
| 2026-11-27 | Triage is one pack tool (`triage`, five actions) that runs deterministic pipelines in the harness and refuses when nothing maps to the tree; suspect commits rank removals of a missing symbol and assignments of a null field above the blame of the failing line | Blueprint First and Holmes: the pipeline, not the model, should do the log → stack → module → commit steps; the failing line is where a bug surfaces, not where it was made | 9 |
| 2026-11-27 | Extension tool results go through `taint.observe` (a result's `"taint"` flag, `device:` for device output) | MCP and manifest results were wrapped as untrusted but never raised the session taint | 4, 6, 9 |
| 2026-11-27 | `crit serve` on the stdlib (`http.server.ThreadingHTTPServer` + server-sent events), not `starlette` + `uvicorn` | One thread per request and per event stream is plenty for a handful of local clients; the whole server is ~550 lines with no new dependency, and the OpenAPI contract tests keep it honest. An async server can replace it behind the same spec if many clients appear | 5 |
| 2026-11-27 | `session_log`, `compaction` and `prompt_build` stay sibling engine-layer modules, not `engine/` submodules | `crit sessions` (an app) reads `session_log`, and the other two are self-contained; moving them would only rename imports. The engine package imports them | 5 |
| 2026-11-27 | The engine package's `__init__` is the engine interface for apps (plus `ui_api` and `session_log`); `agent.py` stays as compatibility names that apps may not import | Keeps the engine's internals free to change; old callers and the tests keep working while they move | 5 |
| 2026-11-27 | Engine events are the session log's events (same `seq`); requests (`request`, `request_answered`) and UI output (`notice`, `assistant_text`) are logged too; streaming tool output is live only | One numbering for replay, reconnect (`since_seq`, `Last-Event-ID`) and crash resume; the log stays the single record | 5 |
| 2026-11-27 | A non-loopback `crit serve` needs `--listen ADDRESS --insecure`; no TLS yet | The plan allowed TLS or an explicit acknowledgment; TLS needs certificates crit cannot make safely for the user today. An SSH tunnel to 127.0.0.1 is the recommended remote path | 5 |
| 2026-11-27 | Unattended requests (headless agent runs, `crit run`) are answered at once the way NullUI answers (refuse, no answer, no plan) and logged | A headless run must never hang on a question; the refusal is visible in the events | 5 |
| 2026-11-27 | `crit run` is the headless command only with `--agent`, `--json` or `--url`; otherwise its words are a task | `crit run the tests` was already a natural task | 5 |
| 2026-11-27 | Background jobs a task started are stopped when it ends; `keep_background_jobs: true` keeps them | Stage 2 asked for cleanup at task end; the model was already asked about running jobs before COMPLETED, and jobs from earlier tasks are left alone | 2, 5 |
| 2026-11-27 | Sandbox: our own small bwrap / sandbox-exec layer (`sandbox/`), not Anthropic's `sandbox-runtime` | sandbox-runtime is a Node.js package; embedding it from Python means shipping and spawning Node for every command. The parts crit needs (bwrap arguments, a seatbelt profile, an HTTP CONNECT proxy, a socket bridge) are a few hundred lines of stdlib Python with the same design | 4 |
| 2026-11-27 | `taint.py` sits in the tools layer (interface), not the engine | The tools raise taint (web_fetch, outside reads, device logs) and the egress proxy reads it; the engine needs only one call, `taint.check(perm, mode, approve)`, around its permission decision | 4 |
| 2026-11-27 | In auto mode a command inside the sandbox runs unasked (`Permission.contained`); risky commands, network commands, and outside paths still ask | The sandbox, not the command-line check, is the boundary; this is where the prompt reduction comes from | 4 |
| 2026-11-27 | Strict egress keeps sandboxed commands offline (no proxy for web traffic); the proxy still runs to forward the adb port. With `egress: open` the proxy carries web traffic and logs it | Strict already meant "agent commands offline"; the sandbox must not loosen it | 4 |
| 2026-11-27 | Profiles: an explicit `local.num_ctx` wins over a profile's `effective_context`; `generic` sets no `effective_context` (the plan said 16K) and no sampling; profile values are only those a model card states, and families not checked against a card (Qwen3.8, Gemma 4) get placeholders with `tool_mode` and edit format only | The person's own setting should not be silently overridden; a 16K cap on every unknown model would change chat sizes before the eval shows it helps; invented sampling values would be worse than the server's defaults | 1 |
| 2026-11-27 | Own MCP client (JSON-RPC 2.0 over stdio and streamable HTTP, ~600 lines), not the `mcp` SDK | Only initialize, tools/list and tools/call are needed; no new dependency on a 3.10+ base install; pinning and untrusted wrapping sit in the same file | 6 |
| 2026-11-27 | Extensions are one tools-layer package (`extensions/`) that hands the engine a merged `ToolRegistry`; pre/post tool hooks wrap that registry | Keeps the tools boundary narrow (one registry, no engine special cases) for the later own tool layer | 6 |
| 2026-11-27 | Every project-scope tool, hook and MCP config needs `crit trust` (read-only tools too); project agents and commands load but cannot loosen the mode until approved | A read-only manifest still runs a program from the repo; prompts alone grant nothing | 6 |
| 2026-11-27 | Stale reads: an edit to a file never read in the task applies only when every edit matches exactly (a loose ladder match on unread text is refused); a file changed on disk since it was read is always refused | An exact unique match proves the model has the text (from a search hit, say) and saves a turn on a slow local model; loose matches on unseen text are where wrong edits come from | 2 |
| 2026-11-27 | Edit guard default `flag` keeps Python/JSON/XML refusals: an edit that breaks a file of those kinds that parsed is still not applied; other languages are flagged; `reject` refuses any new syntax error, `off` silences the guard | Those checks are exact and in-process, and the refusal existed and is tested; brace-balance and tree-sitter checks for other languages are rougher, so they flag | 2 |
| 2026-11-27 | Saved full outputs move to `.crit/cache/out/<id>.txt` (newest 200 kept) for every tool, commands included; job logs stay in `.crit/cache/output/` | One place and one rule for recoverable compression | 2 |
| 2026-11-27 | Stage 8 index tools ship as 14 named tools (38 in all), as the plan lists them; `coverage_locate` is not read-only (it runs the failing test and asks like `run_command`); call edges stay name-matched and labelled "likely"; the session-start repo map is left on the 1.0.x refs map until the engine owner switches it | The plan names each tool; the test-count rule ("few tools") is kept honest by measuring with model runs before M3 and merging tools behind an action if a small model picks worse. A tool that runs commands cannot be in the read-only set | 8 |
| 2026-11-27 | Eval models: day-to-day on this laptop with a small Qwen (qwen3:8b on the local Ollama, RTX 3060 6 GB) to check the protocol; representative runs on the user's 27B dense Qwen via OpenRouter (synthetic suite only, never private code); the real crit-vs-opencode baseline on the LAN machine, run from the other machine with `scripts/eval/baseline.sh` | The LAN machine is not reachable from this one; the laptop GPU cannot hold a 27B model | 0, 1 |
| 2026-11-27 | Finding code: minimize search turns (multi-pattern search, counts first, index-backed AOSP search, parallel calls); handle bad names by fusing name-independent signals (string literals/log tags, runtime coverage and stack traces, commit history, plain-language cards, structure, tests, optional embeddings) in `locate`; an obfuscated-names eval set; optional small-model search helper (9.8) | On a local model, round trips cost more than scanning; experts find badly named code by behavior and evidence, not names | 2, 8, 8b, 9 |
| 2026-11-27 | **Revised:** keep the web-chat backend, but as a removable module (`critique_bot/webchat/`, optional `webchat` extra), not removed in Stage 1. Core crit must work with the folder deleted (test + CI job) | User direction: do not remove it for now. Isolation gives the same design benefits (one API-shaped engine) without dropping existing users | 1, 3, 5, 10 |
| 2026-11-27 | Writes: find-and-replace with the match ladder is the main path; whole-file only as a fallback; `apply_patch` only for patch-trained models, with its own parser (no `git apply`); stale-read protection, atomic batched edits and atomic writes; n-gram speculative decoding in server presets, kept only if measured faster | Write time is output tokens, not disk I/O; exact unique matches fail loudly; fuzzy matching cuts edit errors 9x (Aider); a whole-file rewrite on a local 27B model can take minutes | 0, 1, 2 |
| 2026-11-27 | New Stage 8b, Project memory: structure cards, change patterns, episodes, approved conventions, per-task recall as a "hunch", KV primer; replaces 9.7 | User idea: give the agent an expert developer's cached mental model of the project instead of re-reading code every session. Designed against the AGENTS.md study's failure modes (generic, unverified, always injected, stale) | 8b, 9 |
| 2026-11-27 | (Superseded for the web chat by the revised row above.) Drop the web-chat backend completely (Stage 1, first work item); support many local model families and servers via profiles; cloud providers become a future Stage 11 behind the same `Provider` interface | User direction. Removes ~6K lines and the Playwright dependency, and leaves one model path (APIs) to design for | 1, 3, 5, 9, 10, 11 |
| 2026-11-27 | Plan created: 11 stages, 3 milestones; protocol and sandbox first, verification second, scale third | Literature review (`research/literature-review.md`): harness deltas on a fixed model are the measurable edge; native tool calls, edit guards, cache-aware context and a sandbox are the cheapest large wins | all |
