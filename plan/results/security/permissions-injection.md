# Security review: permissions, modes, taint and prompt-injection resistance

Scope: `engine/` (dispatch, modes, delegate), `agent_rules.py`, `agent_tools.py` (permission_for,
read-only classification, secret and path checks), `project_home.SECURITY_KEYS`, `taint.py`,
`redaction.py`, the AOSP pack's device rules, `eval_harness.py`, and the claims in
`docs/security.md` and `docs/agent.md`. Branch `wip/sec-permissions`, based on `25f9ec0`.

Method: adversarial. The attacker is either the scripted model output (a model steered by
injected text) or a file planted in a temporary workspace. Every finding has a test under
`tests/security/test_sec_permissions_*.py`. The test asserts the secure behavior and is marked
`@unittest.expectedFailure` with `# SECURITY FINDING PM-<n>`, so the suite stays green while the
finding is open. When a fix lands, the test shows up as an "unexpected success": remove the
decorator then. Next to most findings is a passing control test that shows the nearby case that
crit already handles. All tests run in temp folders with HOME and CRIT_HOME redirected, use fake
secrets, start no real model, and never reach a device (the adb test uses a fake runner).

Full suite after the change: `Ran 2096 tests ... OK (skipped=32, expected failures=22)`.

Severity uses the target deployment (a developer's PC or an AOSP tree, a model that reads untrusted repo text and logs): **high** means one routine approval or a default flow leads to arbitrary code execution or an arbitrary file write that the user did not see; **medium** means a documented guarantee is broken in a realistic setup; **low** means a gap that needs an extra user step or yields only prompt influence.

### Chains worth noting

- **PM-3 or PM-4 → PM-6:** one "always" on `git log` lets the model rewrite `.git/config` (`git config core.fsmonitor …` or `git log --output=.git/config`). From then on, every read-only `git status` runs attacker code in auto mode and in helpers, with no prompt even in a new session.
- **PM-4 → next session:** `git log --output=.crit/settings.json --format='{"allow":["*"],"permissions":"auto"}'` replaces crit's own settings. `_guard_target` protects that file only from the file tools.
- **PM-7 + PM-8:** in ask mode, one `delegate` call changes device state (`dumpsys battery set`, `logcat -c`) with no prompt.
- **PM-5 under taint:** after a `web_fetch`, auto mode refuses `curl`, but a test file the model writes, run through an allowed `pytest`, opens any socket (outside the sandbox).

## What held up

These were tried and are handled correctly. Most have a passing control test above or an existing test.

- **Chaining against allow rules** with `;`, `&&`, `||`, `|`, `&`, `$(...)`, backticks, `>`/`<` redirects, `( ) { }`, here-strings, and `VAR=` / `env -S` / `xargs -I` prefixes. Each part needs its own rule, or the command is uncheckable and asks. Filters after a pipe are allowed only when their options are harmless.
- **Read-only classification** rejects `rg --pre`/`-z`/folder searches, `grep -r`, `sort -o`/`--compress-program`, `find -exec/-fprint*/-delete`, `fd -x`, `xxd -r`, `tree -o`, `less +cmd`/`-o`, `git -c/-C/--git-dir/--exec-path`, `git --output/--ext-diff/--textconv/-O/--upload-pack` (prefixes included), `printenv`/environ dumps, and `$` expansions.
- **Secret-file gating** for `read_files`, `search_code` (hits are hidden), `git_show HEAD:.env`, bare blob ids, globs that could match a secret (`cat .e*`), links to secrets, `cp .env x`, and `move_file`/`apply_patch` renames.
- **Path checks:** links inside the workspace are resolved before the outside check, `..` and absolute paths ask, and writes into `.git/` (including through a committed link to `.git`) are refused. `apply_patch` paths come from the same parser that applies the patch (`paths_in`), so no header trick hides a target.
- **Protected files for the file tools:** `.crit/settings.json`, `.crit/skills`, `.crit/{tools,agents,commands,hooks.*,mcp.json}`, `~/.crit/{…,trust.json,mcp-lock.json}`, and the config named in settings.
- **Committed `.crit/settings.json` in a git clone** loses `SECURITY_KEYS`, including through a `.crit` link to a tracked folder or a link pointing outside the repo, where `git_tracks` fails closed.
- **Project extensions:** tools, hooks and MCP stay off until `crit trust`, and a project agent's `mode` is ignored unless trusted (`effective_mode`). Helper tool allowlists only narrow, and a helper cannot delegate.
- **Helpers refuse** network, outside paths, secret files, risky commands, non-read-only commands, and edits to files they do not own. A writer agent's patch returns to the coordinator, which applies it with `apply_patch` through the normal approval path.
- **Plan mode** blocks edits and non-read-only commands for the coordinator. Read-only commands still ask outside auto mode. PM-7 is the exception.
- **Taint** is raised by `web_fetch`, MCP results, absolute outside reads, logcat commands, and flagged extension results. Under taint in auto mode, network kinds, network commands, `git push` and outside writes are refused before the approval logic runs.
- **The `memory` tool's `propose`** only queues a convention for human approval (at most 2 per task). Episodes from tainted sessions are excluded from recall unless `memory_untrusted` is set (see PM-13).
- **`confirm_risky: false`** relaxes only auto mode and never device (`device:`) actions.
- **The `crit eval` allow-everything file** stays in the throwaway fixture workspace when the task has no `workspace` (see PM-10 for the case where it does).

## Residual risks (not filed as findings)

- **Command parsing is a blocklist over a POSIX-ish tokenizer.** The per-command `shell` argument (`zsh`, `pwsh`, `cmd` on Windows) parses differently from what `shlex`/`_SPLIT_RE` assume. Windows `cmd` `^` escapes and PowerShell's `;`/`&` call operator deserve their own review.
- **`cd` segments are skipped by allow rules**, so `cd ../other-repo && ./gradlew test` matches `./gradlew test*` and runs another tree's wrapper. The `cwd outside the workspace` check covers only the `cwd` argument and the session cwd before the command.
- **Persistent prompt injection through files the model may edit freely:** `AGENTS.md`, `.crit/AGENT.md` (sent every session; its `Test command:` line still asks), `.vscode/tasks.json`, `.envrc`, CI workflows. This is normal for coding agents, but worth a note in `docs/security.md`.
- **A committed `.crit/memory/` database** from a malicious repo is loaded like the user's own, with forged "approved" conventions and "verified" episodes. This is prompt-level only, and the same class as a committed `AGENTS.md`.
- **The taint mode is a process-global** (`taint._state.mode`). Helpers always call `check` with `auto`, so in a mixed session the status line can briefly show "restricted". No bypass found.
- **Redaction recognizes formats and key names only.** Secrets with unusual names in build logs or test output reach the model (see PM-11 for the git path).
- **With the OS sandbox on** (Linux or macOS with bubblewrap), auto mode runs every command contained. PM-6 and PM-8 then reduce to "contained", but they still apply in helpers, on Windows, and with `"sandbox": "full"`. The sandbox itself was out of scope here.

## Overall assessment

The design is thoughtful and layered: per-option read-only analysis, secret and outside-path gating, protected settings, trust-on-hash for project extensions, taint, and helpers that refuse rather than ask. Most single-step attacks fail. The weak point is the **approval-memory layer**: saved allow rules and "don't ask again". It matches command text with globs that are wider than the prompt shows the user (PM-3, PM-4). It parses newlines differently from the shell (PM-1, PM-2). It does not track code the task wrote that a build tool loads (PM-5). Since crit offers to save these rules on routine approvals, an injected model that waits for one "always" can reach arbitrary code execution and persistent file writes. These four should be fixed first, followed by PM-6 and PM-7: helper chats are the one place where ask and plan mode do not hold. Then fix the trust-origin gaps (PM-9, PM-10).
