# AOSP agent tasks

This is a suite of tasks for coding agents that work on the Android platform and Android
Automotive. They cover crashes, ANRs, native crashes, SELinux denials, build breaks and
test selection. Each task is graded by a program, not by a person. It starts here, in crit's
own suite. The plan is to move it to its own repository with a leaderboard of harnesses on
fixed models (plan/09, section 9.2).

## Why synthetic first

No agent benchmark for AOSP exists. A real tree is about 450 GB, and grading on it needs a
lunch target and hours of building. These tasks use small fixture trees that look like AOSP:
real `Android.bp` shapes (filegroups, defaults, `instrumentation_for`), `TEST_MAPPING`
files, threadtime logcat, tombstones, ANR traces, dmesg with `avc:` lines, and Soong, javac,
clang and lld output. Each task runs in seconds with `python3`, `git` and, for two tasks,
`g++`. Tasks on a real tree (`"workspace": "$AOSP"`, like `aosp-module-owner`) come
later, once a pinned tree and build exist.

## The tasks

| task | kind | what the agent must do | graded by |
|---|---|---|---|
| aosp-crash-root-cause | crash | find the root-cause exception and line under a framework-only top of stack in 60k lines | answer |
| aosp-crash-module | crash | map a crash in a filegroup file to the app module to rebuild | answer |
| aosp-crash-suspect-commit | crash + git | name the commit that made a field null (not the newest commit, not the blame of the crash line) | answer |
| aosp-crash-not-in-tree | crash, refusal | say the crashing code is not in the tree, despite a same-named class in another package | answer |
| aosp-anr-lock | ANR | find the thread holding the main thread's lock, and what it does while holding it | answer |
| aosp-tombstone-symbolize | native | symbolize a stripped frame with the tree's `symbols/` and addr2line | answer (needs g++) |
| aosp-tombstone-abort | native | find the aborting function and the cause without symbols | answer |
| aosp-selinux-sysfs | SELinux | pick the blocking denial out of hundreds and add exactly the minimal rule | check |
| aosp-selinux-generic-label | SELinux | refuse an allow on a generic label; add a type, a genfscon line and the rule | check |
| aosp-build-missing-dep | build | add the library that provides a missing package to the right `static_libs` | check |
| aosp-build-undefined-module | build + git | follow an upstream module rename instead of undoing it | check |
| aosp-build-cpp-member | build | fix the C++ caller of a renamed method; compile and run a check | check (needs g++) |
| aosp-tests-for-change | Soong | select the TEST_MAPPING and instrumentation tests for a change | answer |

## Rules for a task (same as the rest of the suite)

- Each task is a folder with `task.json`, `files/` (the tree the agent sees), and either
  `answer` with `reference_answer`, or `check` with `hidden/` and `solution/`.
- `crit eval audit` must pass: the check fails on the untouched tree and passes with the
  reference, and the reference answer matches the answer regex.
- Checks run offline, in under a minute. A check must not pass when a test is deleted or a
  rule is broadened (wildcards, extra permissions, a reverted upstream change).
- Logs are generated by a seeded script in `files/` (`gen_log.py`, `make_history.py`), so
  the repository stays small and every run sees the same bytes.

## Running

```bash
crit eval list --tag aosp
crit eval audit --tag aosp
crit eval --tag aosp --runs 3 --config <model config>                  # without the AOSP pack
crit eval --tag aosp --runs 3 --config <model config> --packs aosp     # with it
crit eval compare <results without> <results with>
```

Another harness runs the same tasks through a runner (`--runner opencode`). For a published
number, record the model, quantization, server, context size and the harness version in
`--note`.

## Before the public repository

- About 40 tasks, at least 5 per kind, plus HAL bugs and CarService behavior (plan/09 9.2).
- Each task's provenance: the real failure it is modelled on, where there is one.
- A fixed, documented model set and server settings for the leaderboard; pass@1 and
  pass^3 per harness, with paired bootstrap intervals (`crit eval compare`).
- A license for the fixtures (Apache-2.0, like the AOSP code they imitate) and a
  contribution guide for new tasks.
